# Local automatic catalogue reuse implementation plan

**Closed: workload measurement delivered; conditional optimizations not activated.** Task1 and its correction are complete and reviewed. The later catalogue-reuse tasks remained gated by measured usefulness and were not dispatched. A separate journal-write experiment completed the fixed comparison and was not promoted. See [the final QA record](../../qa/2026-11-23-automatic-catalogue-performance.md).

> **For agentic workers:** Use the programme’s selected implementation and review workflow. Steps use checkbox syntax.

**Goal** Reduce repeated catalogue materialization on an ordinary model-bound local analysis attempt and quantify the result on a real automatic job.

**Architecture** The catalogue service issues an immutable view only after verifying the retained generation and bytes. The local continuation owns it from admission through execution. Each authority boundary independently checks the source. The command, serialized authority, continuation signature and result keep their existing formats.

**Tech stack** Java 25, Spring transactions, Hibernate/JPA, HSQL, Jackson, JUnit and the existing deterministic scenario provider adapter.

**Spec** Read docs/superpowers/specs/2026-11-23-automatic-catalogue-workload-design.md alongside docs/superpowers/specs/2026-11-23-automatic-performance-program-design.md.

## Global constraints

Keep existing access checks, transaction and claim ownership, lease, cancellation/PAUSED, fresh question/provider policy checks, historical identities and supported database dialects. Preserve independent model attempts, accepted reply persistence, budgets, heap guards, timeouts, QA gates, exports and evidence. No lock or database transaction across provider HTTP. No new shared mutable tree/cache or worker thread-local. Run one Maven process at a time using the established Java 25 environment.

## Review focus

1. A same-row same-length payload mutation during the ambient portfolio transaction must fail before claim. Also test fresh execution in a separate transaction (tasks 2–3).
2. The historical generation must survive changes to the current pointer. A changed timestamp, relation reference, source, binding or roots must prevent reuse (tasks 2–3).
3. Concurrent local attempts and failures must release their scopes and return independent mutable results (tasks 2–3).
4. Existing request signatures must match byte-for-byte for non-ASCII evidence, old requests and distinct scope/language/reason policy (task 3).
5. A real automatic relation slice is different from a newly admitted continuation attempt. Account for both and for provider waiting separately (task 1).
