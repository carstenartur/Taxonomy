# Stable analysis diagrams and complete print sheets

## Intent

Readers must be able to inspect an evolving analysis without losing their zoom,
position or opened branches. The same relevance selection must determine the
nodes shown on screen and in diagram printing. A scored node's available reason
must reach the browser before the complete analysis has finished.

## Decisions

- Retain per-view reading state during repeated renders. SVG and Canvas trees
  share a logical view; different selected taxonomies keep separate state.
  New analysis/requirement contexts must not inherit an unrelated viewport.
- Reuse the existing non-mutating relevance projection for all taxonomy-browser
  views. Positive-only means a finite effective score greater than zero; retain
  ancestors for context without adding unassessed siblings. Pending product
  suitability is not an effective positive relevance score.
- Keep compact shared controls for relevance, applicable tree expansion,
  zoom/reset/fit and print. Reuse existing labels and APIs where possible.
- Propagate already recorded reasons through live progress and terminal streams.
  Preview retention remains bounded and reports omissions; full results retain
  authoritative evidence. Missing reasons must not be generated by a display action.
- Keep existing readable A4 continuation pages. Add a paper selector for complete
  sheets (A4 through A0) and a separate layout choice: complete diagram on one
  sheet, or one sheet per selected subtaxonomy. Complete sheets use connected
  measured tree geometry, not an arrangement of fragmented A4 pages.
- Print the selected hierarchy, percentages and complete saved reasons, including
  collapsed branches. Preserve screen reading state and all stored analysis data.

## Approaches considered

Rebuilding the entire visualization framework would expand this repair and risk
existing keyboard and export behavior. Persisting only the zoom transform would
still lose branch expansion, Sunburst focus and scroll position. The chosen
approach retains reading state around the existing renderers and reuses their
measured layouts and common projection for print.

## Constraints and verification

Keep Java 25, Maven-owned tests, existing workflow selection and catalogue
identity. Add no visualization dependencies or model calls. Verify redraw behavior
in real Chromium; verify PDF physical dimensions, page counts, node/reason
selection and complete text. Test running progress and terminal event reasons.
Document local focused results separately from the required full CI/container gate.
