# Versioned architecture scope and recoverable delivery

An architect can bind several exact portfolio requirements and supporting text excerpts to a brief in one reviewed change. The canonical brief retains portable project and requirement keys, version numbers, content hashes and exact quotes. A scoped server operation resolves the current portfolio identities and locks all affected projects when accepting. An old checkpoint continues to show its original brief. Existing brief records read with an empty binding list.

The application keeps accepted ADMBw delivery identity in the existing integration journal and checkpoint view. Before submitting an acceptance request the browser records its operation identity and scope. Reload looks up that same operation in the selected workspace. The user supplies the original QEA file again. The server compares its hash to the recorded delivery basis. A missing or pending publication remains visible.

Structural findings remain derived from the model. Known issue codes take the architect to the appropriate canonical planning or assignment form for a fresh edit and review. A historical checkpoint presents findings read-only. Unknown codes retain their explanation.

A QEA preflight checks the same immutable source, whole-model coverage and writer restrictions as native export. The optional plugin owns all SQLite and native validations. Preflight leaves the uploaded basis unchanged and returns no native artifact. Native Enterprise Architect inspection remains a separate acceptance step.
