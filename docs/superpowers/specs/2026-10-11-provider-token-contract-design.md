## Proposed narrow supported adapter

An explicit quota adapter `openai.responses.gpt-4o-mini-2024-07-18.v1` selects the named snapshot and stateless Responses wire only when OPENAI has active TPM. TPM-off preserves the exact existing Chat Completions endpoint, body, recording behavior and frozen provider fingerprint. Unknown adapter IDs, other aliases/endpoints/models and other providers retain their existing 0-HTTP failure.

Prepare one immutable complete model/input payload: fixed snapshot plus a single user-role text input containing the entire authored prompt, including system instructions/catalogue already embedded in it. There is no server conversation, prior response, tools, files, remote URLs, dynamic prompt or hidden state. Both count and generation explicitly set `truncation:"disabled"`; neither may silently discard leading input. Before count, enforce fixed serialized request-byte, total operation-time and response-byte limits. These are transport bounds, not guessed token ratios, and also apply to oversized or rejected count responses. Send that exact input shape to `/v1/responses/input_tokens`, parse strict integer nonnegative `input_tokens` and exact object discriminator, and reject above configured input bound. Only then emit generation with the same input/model, actual `max_output_tokens`, `store:false`, and no stateful references. Reject incomplete, refused or structurally unexpected output. Meter parses the actual Responses usage fields, never converts a count response into known inference usage.

Count itself is a physical external operation: every count attempt and generation retry acquires the ordinary local/distributed permit, ordinary cancellation/deadline checks, durable shared admission and durable diagnostic START, using distinct physical IDs. 429 updates the same shared cooldown even when retries are exhausted. No bypass using a null token budget is added. The approved conservative contract charges the existing full configured token reservation for each count and retains it as UNKNOWN until normal window expiry, including unsuccessful or rejected counts and every retry; it does not grant an unsupported free/zero-TPM path. Count never produces known inference usage or refunds even if an invalid response contains a usage-shaped field. Generation uses a fresh full reservation after exact complete-input validation. Counts are tokenizer operations, not generation; the published contract does not establish vendor billing/TPM exemption, so the operator-facing claim remains actual inference tokens, separate from upstream rate-estimation behavior.

Freeze provider identity with adapter version, pinned snapshot, complete-input schema version, exact configured input/output bounds, actual cap and endpoint. Existing invocation/scoring/relation hashes therefore reject a semantic quota/model change on resume. TPM-off identity remains byte-identical. Request and count bodies/credentials never enter JMS, management diagnostics or logs.

## Required executable evidence

Loopback HTTP fixtures must inspect complete actual count and generation bodies, Unicode, full system/catalogue text, all roles, no hidden state, immutable model and actual output cap. Oversized/negative/fractional/overflow/missing/trailing/unknown count response, wrong endpoint/adapter/model and unsupported providers produce zero generation calls. Missing durable admission/START or lost broker ACK produces zero count/generation calls. Each real count retry and generation retry is charged before HTTP. Real 429 propagates cooldown across independent clients. Cancellation during count, between count and generation and while waiting for permits creates no later generation. Count response is not known provider usage or a saved semantic answer. Actual Responses usage including cached/reasoning fields settles conservatively; absent/invalid/over-bound usage retains or blocks according to existing ledger rules. Recording replay invokes neither endpoint. Saved continuation answer restart invokes neither endpoint; changed bound/adapter/model fails frozen identity.
