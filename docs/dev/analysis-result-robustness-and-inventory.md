# Result robustness and export inventory

## Reproduced defects and bounded corrections

The reported work-time requirement produced an otherwise structured relation answer inside a Markdown JSON fence. The relation protocol now removes only one complete whole-response `json`/bare fence. It does not salvage an arbitrary inner object, guess IDs, accept duplicate keys, invent evidence quotes, or change the raw response stored for diagnosis. Missing, empty and oversized responses have separate errors. The source prompt distinguishes functional interpretation across languages from literal word occurrence in catalogue descriptions.

The first nine-test JUnit regression commit reproduced the failure in GitHub CI. The correction preserves the existing strict semantic boundary. Automatic split/retry of malformed source groups is not implemented by this narrow correction.

Visio formerly used green for anchors, making all-anchor exports uniformly green. Fill now uses the same taxonomy-family palette as the PDF; the stronger border marks anchors, never human acceptance. Canonical IDs and recorded taxonomy depths are also printed on shapes, while full values remain in shape data.

PDF labels are measured after transliteration using the actual font metrics. Display labels may use an explicit ellipsis; the appended paginated inventory retains their complete printable text. This remains a Standard-14-font export, not a new Unicode font implementation. Pages that would require unreadable scaling fail explicitly instead of allowing a minimum font size to overflow a shrunken box. The supplied screenshots, not a user's original PDF/VSDX file, were available; generated offline fixtures provide the geometry regression.

## Count scopes and approval

The browser status paragraph reports unique loaded nodes, per-taxonomy counts, navigation containers, positive assessments in the loaded set, and the captured architecture's unique endpoint/type relationships. It is event-driven and makes no additional requests. Counts do not claim to enumerate an unloaded catalogue or backend work queues. AI-backed proposals are shown separately; legacy/seed/trace provenance must not be relabelled human confirmation.

PDF inventories count the exported scene. Word/HTML decision reports count the full selected decision tree, not the top-ranked leaves. Saved architecture Word sections include element/container/relationship and taxonomy-family counts, without double-counting repeated detail figures. The neutral diagram contract does not carry human acceptance; documents say that it is not recorded rather than inventing a confirmed count.

## Fractional hierarchy scores: confirmed remaining work

The current analysis contract stores integer percentages in AnalysisResult and node DTOs, parses exact integers, and uses integer largest-remainder apportionment. Browser category/product handling also rounds to integers. Thus a 1% absolute parent budget cannot represent two 0.5% children, and deeper positive branches can be lost. Export formatting preserves fractions that already exist in the neutral diagram, but cannot recover values lost upstream.

A compatible numerical migration must cover the parser, typed scores/DTOs, category traversal, product effective relevance, persisted snapshots and checkpoints, recovery policy identity, filters, UI and all export adapters together. Root relevance remains independent per taxonomy. Category children share the inherited parent budget; local shares must be distinguished from absolute relevance. Product suitability remains independent, with effective relevance obtained from its category contribution. Explicit zero, missing assessment, technical failure and unresolved work must remain distinct.

Required examples: 1% split equally -> 0.5% + 0.5%; four children below 0.5% -> 0.125% each; a long single-child chain retains the same absolute budget. No positive score may be pruned because of display rounding. Do not use a 1% floor, silently rescale every level to independent 100%, or reinterpret old integer snapshots as new units. This end-to-end migration is not included in the export correction.

## Verification ownership

All committed regressions are owned by the existing Maven/JUnit build, including the small Node DOM contract invoked by ResultStatisticsTest. There are no new workflows, provider calls, coverage exemptions or test exclusions. Renderer compilation and local generated-PDF inspection are useful targeted evidence, not a substitute for a complete Maven reactor result or a real Visio desktop interoperability check.
