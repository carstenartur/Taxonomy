# Feasible VSDX graphical quality completion

Scope and authority: the user requested completion of export quality and the feasible #1075 work without Sparx. Actual LibreOffice Draw evidence identifies repo-owned caption and layering defects. This specification implements that correction; it does not claim EA diagram synchronization or Microsoft Visio product acceptance. The inspected civilian Draw output showed captions without complete text transforms, overlapping labels and strokes above nodes; changing TxtAngle alone collapsed the default text boxes. A complete TxtXForm is required.

## Design

Use the existing Visio export owner and preserve the full canonical overview plus optional anchor/impact page. Keep editable 2-D node shapes, native 1-D connectors, exact canonical IDs/source/target/type/relevance/provenance and the current dynamic walking glue/rotating transform. The exporter continues to accept the existing supported graph bounds and reject existing unsupported self-loops; no unrelated semantic expansion.

1. Add complete, finite text-box geometry for connectors. Text remains upright in the page coordinate system after normal ShapeSheet recalculation as well as with cached values. TxtAngle alone is insufficient. Maintain its relative-angle relationship to the existing connector transform. Text positions must avoid node text and other placed captions. Use deterministic bounded candidate placement and explicit dimensions; no unbounded search or tiny-font escape.
2. Render crossing connector strokes behind opaque node bodies so the full overview cannot draw lines over node text. Do not change endpoint/dynamic-glue identity. Preserve type as semantic data independently of any compact display key. For a dense overview, compact stable relation keys are acceptable if the associated complete type/direction and readable native details remain accessible. If a caption cannot be placed without collision, use an explicit documented presentation disposition instead of drawing overlapping text or silently treating it as legible.
3. Add bounded native relationship detail pages when a whole overview is dense or caption placement is incomplete. Deterministically partition all required relation details into small subgraphs (at most six distinct endpoints and six relations per detail page); endpoints are unique per page and may repeat on other pages. Each detail includes identifiable canonical node and relation keys, direction and readable type, retains exact native shape data, and uses ample geometry so no caption obscures node text. Distinct coincident/multiple/reverse edges remain distinguishable. Stable ordered source IDs determine page membership, not display titles. Avoid a new generic diagram framework; a cohesive helper in taxonomy-export is appropriate. Do not depend on taxonomy-architecture to reuse Word code.
4. All 44 relationships of the current ordinary civilian graph must have a readable native detail or a clear uncluttered overview representation, with automated coverage and actual rendered evidence. Detail-page growth is capped by the existing global 32-page, 20,000-shape and 60,000-connector budgets after reserving complete overview and impact pages. No budget inflation and no rejection of a previously valid large graph just because optional detail space is exhausted. Complete canonical overview/shape data is never dropped. At the limit, include a truthful bounded presentation loss/count/covered range and document how to inspect remaining native shape data or use the complete report inventory. Do not claim every arbitrarily large graph is visually exhaustive within 32 pages.
5. Preserve full saved labels in semantic data. Long/non-ASCII labels need bounded readable wrapping/geometry and explicit truncation disposition where necessary; no malformed XML, overflow geometry or hidden source loss. Any new presentation-only keys are clearly separate from canonical semantics and do not invent extra model relationships.

## Acceptance

Meaningful regressions reproduce reverse/vertical captions, coincident multi-edge collision, line-over-node layering and dense-graph readability/coverage. Test geometry numerically and native source/target/type/key/properties/glue preservation; cover deterministic page membership, exact boundary budgets, no loss of complete overview for large inputs and long Unicode labels. Existing package/schema/POI/contract/dynamic-glue tests remain required. Adjust old positional/count expectations only where additive detail output intentionally changes them, preserving their original semantic assertions. No test weakening.

Use the real civilian saved-snapshot workflow and existing check-civilian-documents Draw/Poppler path. Extend its VSDX check beyond 38 node-label presence to canonical relationship coverage and actually rendered key/type evidence. Retain machine-readable coverage, renderer version, exact source/artifact hashes and every changed page image. Controller views every changed page. Microsoft Visio and EA/PCS remain NOT_EXECUTED.

Update EN/DE user docs and QA disposition with the new overview/detail behavior, stable keys, native editability and limits. Keep diagrams generated by exporter code; no raster substitution, AI-created evidence or invented screenshots. Final whole-root/CI gate belongs to controller.

## Byte-budget clarification

The existing 32 MiB total uncompressed package limit also remains unchanged. Input graph limits and package acceptance bounds apply together: the 10,000-node/30,000-edge model remains fully represented in memory but can independently exceed the package-byte limit. Optional detail pages must never cause rejection of an otherwise valid overview/impact package. The package builder counts exact UTF-8 part bytes, removes only explicitly marked optional trailing detail pages, reuses retained page XML and recomputes coverage before the unchanged validator runs.
