# Packed portfolio analysis snapshots implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans task by task. Checkboxes track execution. Root owns the authorized programme and release gates.

**Goal:** Reduce the amount of stored analysis text JDBC must read and fingerprint while preserving the existing snapshot evidence and policy contracts.

**Architecture:** Complete reader compatibility precedes writer activation. An independently configurable default-off writer uses the existing portable v1 representation for eligible new values. The memo still verifies the exact stored code units. File-HSQL measures write and read costs together before any broader activation.

**Tech Stack:** Java 25, Jackson 3, Hibernate/JPA, Spring Boot, HSQLDB, PostgreSQL, SQL Server, Oracle, Maven/JUnit. No new dependency.

**Spec:** [packed snapshot design](../specs/2026-11-23-packed-portfolio-snapshots-design.md). Implementation paths below are relative to the active checkout. P denotes taxonomy-portfolio/src/main/java/com/taxonomy/portfolio; PT denotes taxonomy-portfolio/src/test/java/com/taxonomy/portfolio; AT denotes taxonomy-app/src/test/java/com/taxonomy.

## Global Constraints

- Encode only req_analysis_snapshot.analysis_payload. Keep every existing plain row readable, including over 24,000,000 code units. Preserve public JSON, null handling, exports and history.
- Use the existing taxonomy-json-payload:v1 frame. Bound decoded **frames** at 24,000,000 UTF-16 units. Above that size store the original plain value. Preserve all existing export quotas.
- Keep scoped queries, normal full DTO validation on cold/change and complete stored-stream fingerprint checks on hits. Publish after database reader close/locator free succeed.
- Default packed writes to false in every profile. No schema changes, bulk rewrite, production restore enablement or global ObjectMapper changes.
- Use current Java 25 Maven environment and run one Maven process at a time. Read the 18,929,372-byte fixture in its shared artifact directory; do not add or duplicate it under the checkout.

## Review Focus

1. An invalid frame encountered after a parser has stopped must fail; late close/free exceptions must remain observable (Task 1).
2. A same-ID equal-length replacement may change unused fields. Rebind a valid changed payload or reject corruption before returning policy (Task 1).
3. A frame, exact text, raw field absence, unpaired surrogate or different Unicode spelling must survive public export and frozen evidence replay unchanged (Task 2).
4. Mixed-version rollout and rollback must keep plain-only readers away from framed rows; turning off the writer does not downgrade stored rows (Task 3).
5. A very large valid historical payload and an ineligible large new write must retain all data and avoid a new quota error (Tasks 1–3).
