# Synthetic VSDX acceptance fixture

`representative.visio.zip` is generated by `VisioHandoffContractTest.fixtureDocument()` and its `main` method. `committedFixtureIsReproducible` compares it byte-for-byte with the current exporter. `SHA256SUMS` binds the ZIP plus its extracted VSDX/profile. The normal commit-bound CI report identifies the exact source revision that passed the fixture test.

All authority/review values are synthetic. In particular the all-zero `authoritativeCommit` is sample data, **not** a release source SHA or a completed product-certification record.

| Object | Fixture value |
| --- | --- |
| `CP-01` | Capability, score 0.9, anchor/impact selected, review `CONFIRMED` |
| `BP-02` | Business process, score 0.7, impact selected, same Unicode display name as `CP-01` |
| `CS-03` | Core service, score 0.4, outside the impact selection |
| `relation/α` | `CP-01` → `BP-02`, `SUPPORTS`, score 0.8 |
| `relation/β` | `BP-02` → `CS-03`, `USES`, score 0.6 |
| Primary page | Three elements and both connectors |
| Impact page | `CP-01`, `BP-02` and `relation/α` |

Names include accents, Japanese characters, XML delimiters and an emoji. The human rationale deliberately begins with a formula-like string; tests ensure it is emitted as a literal value without an `F` formula attribute.

The automated secondary consumer is Apache POI XDGF 5.5.1 with XMLBeans 5.3.0 and the full Visio schema JAR. Both pages load and render with Java 21 on Linux. Observed previews lack Japanese/emoji glyphs and arrowheads; successful POI loading/rendering does not certify visual fidelity or Microsoft Visio edit/save behavior.
