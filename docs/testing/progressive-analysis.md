# Progressive requirement analysis

Open **Preview changes to the requirement** on the Analyze page. After a short pause in typing, the application ranks the selected catalogue and shows the matched paths. The preview identifies the local method and catalogue revision. If retained ONNX vectors are unavailable, it can use lexical matching. The 300 ms debounce is the delay before submitting the local request. Response time also includes catalogue access, inference and rendering. An empty, open preview can warm the local catalogue vectors.

The provisional architecture groups directly matched entries by their actual taxonomy. The server identifies navigation-only roots and area wrappers using the entire retained hierarchy. Component positions follow source order, with the catalogue code breaking ties. The local score measures a match to the text. Shared title terms are vocabulary evidence. They do not become architecture edges.

**Run detailed analysis for this version** starts the selected provider through the same managed analysis and recovery path as ordinary analysis. A writable workspace, an available automatic provider mode and a valid selection are required. Existing unbound or edited results can be reviewed through the normal analysis controls. Typing or refreshing a catalogue preview never starts this provider work.

Refreshing the preview retires its previous confirmation immediately. The detailed action becomes available again only after the replacement preview succeeds. Its candidates and assessed-score labels remain bound to that confirmed result.

As accepted scores arrive, the matching components and tree paths show assessed relevance alongside the local match. A product assessment awaiting its parent remains unassessed in the preview. The main Decision Map covers assessed nodes beyond the bounded local candidates. Switching views allows the run to continue. Changing the input, provider, scope, model source or analysis language retires the preview-owned run and requests cancellation in its original workspace. Provider cancellation is cooperative. An unconfirmed cancellation identifies the original run in the analysis diagnostics. Already delivered calls may have consumed quota. If a detailed START response is lost, the application checks the saved continuation without resubmitting the analysis. Its verified result can still supply the final scores and architecture. Revoking an extension preserves its prior accepted source and protects subsequent manual edits.

The detailed result retains its completion, partial, failure or cancellation status. When the selected analysis produces an architecture, **View assessed architecture** opens that analysis source. Relationships become available with its canonical result. The preview does not apply edits to the working architecture. Run observation, review, saved evidence and architecture adoption keep their usual permissions and lifecycle.

Confirming a manual node assessment retires the active preview-owned refinement before changing the score or reason. A competing local evidence change also prevents a later provider response from replacing it, whether the response arrives directly, through Artemis or from the saved journal. The existing recovery view lets the user explicitly adopt the saved result without starting another analysis.

## Focused verification

- `CataloguePreviewIndexTest` covers root/area eligibility even when the child that establishes a wrapper is outside the result. `SemanticCataloguePreviewTest` covers semantic and lexical selection. `AnalysisApiControllerTest` checks an execution catalogue changing after preview.
- The registered `ux-state-recovery.cjs`, `analysis-cluster-recovery.test.mjs` and `analysis-recovery.test.mjs` exercise explicit starts, cancellation ownership, pending product interpretation, edit-and-revert, scoped terminal results and preserved manual evidence.
- The registered `analysis-ux.browser.test.mjs` exercises this component with the real preview markup, styles and translations at 390 px and 1180 px in both languages. Its catalogue names and hierarchy are from the bilingual workbook. Its transport and scores are deterministic fixtures. Setting `TAXONOMY_UI_OUTPUT_ROOT` captures the partial-result display.
- To measure real latency, record the model identity, catalogue revision, language, request text length, local method and cold/warm state. Time local catalogue preparation and the ranked response separately from provider assessment. Use an explicitly approved provider test path for remote calls.
