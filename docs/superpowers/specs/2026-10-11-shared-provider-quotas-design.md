# Shared physical provider quotas (Task4C)

## Intent and existing authorization

Complete the remaining issue1161 quota behavior after the separately verified durable continuation package. All actual HTTP attempts in built-in OpenAI, Gemini and contributed gateways must share configured credential/provider groups across workers. Existing broker concurrency permits, continuation ownership and replay behavior remain independent. Root instructed isolated native implementation, genuine RED/GREEN evidence, no paid calls and no new heavy test fork without scheduling.

## Chosen mechanism and alternatives

Use one administrator-provisioned durable Artemis state message per explicit credential/quota group. A short transacted consume/update/replacement serializes debits, usage settlement and cooldown. Commit is confirmed before physical HTTP. Runtime never creates or replenishes a missing queue/ledger. This broker-backed rolling-window ledger avoids holding an unacknowledged rate token through HTTP, which would refund an uncertain request on worker death. A durable token per TPM unit is rejected because message volume scales with tokens; a shared database poller is rejected because the approved broker design excludes fixed pending-row scans.

RPM and TPM use a conservative rolling60second window; RPD uses rolling24hours, which is stricter than a calendar-day provider budget. The neutral admission port returns either a committed opaque reservation or a bounded wait. It never contains prompts, credentials, endpoint URLs, tenant names or catalogue payload. Every retry generates its own reservation and physical-attempt identity. RPM/RPD are never refunded after committed admission. Missing/invalid usage and uncertain transport retain the full TPM reservation until expiry. Exact known usage can reduce that reservation once; duplicate, foreign or late settlement cannot mint quota.

## Integration and waiting

LlmRequestAdmission first retains existing local admission, then checks shared quota before physical send. When a quota cannot currently admit, any HTTP concurrency permit and provisional local RPM reservation are released before cancellable waiting. After broker concurrency acquisition it rechecks and commits quota at the physical boundary. Shared Retry-After updates preserve the longest deadline, including when the local retry budget has ended. Failed/uncertain debit commit admits zeroHTTP; failure to settle keeps the reservation conservative. Recording replay returns before admission and never reserves provider quota.

LlmTransportMeter records/observes the same opaque physical-attempt ID as the quota reservation and supplies actual validated usage for settlement. Durable diagnostic admission still precedes HTTP and remains fail-closed. A journal failure after quota admission keeps the conservative debit; no automatic compensation is allowed.

## Time, bounds and policy identity

Do not claim JMS timestamps or scheduled-delivery timestamps are server-authoritative. All nodes and the broker must maintain the configured maximum UTC clock error. A reservation expires only after window + twice that error, so differing clocks within the declared bound cannot release it early. The ledger carries monotonic observed time; a backwards node outside the declared bound fails closed. Forward clock violations cannot be proven from a single isolated client, so bounded clock synchronization is an explicit operational prerequisite and production acceptance checks it. Tests inject opposite extreme skew, backwards violation and restart; no silent clock fallback.

The durable message includes schema, exact quota-group and policy fingerprint. Workers with mismatching limits, token adapter or clock parameters fail closed. Maximum reservations and JSON bytes are bounded; a full/corrupt/missing/duplicate ledger fails closed. Provisioning is explicit and repeated provisioning must never add capacity.

## TPM transport contract

TPM requires a proven conservative input upper bound and an actual provider-enforced complete output cap. Approximate bytes/4 and estimated chat framing are insufficient. The first supported adapter may reserve an entire documented model input/context limit plus a sent max_completion_tokens cap; its exact supported model contract and request body are tested. Unsupported OpenAI-compatible models, Gemini variants without a proven complete cap, and unchanged contributed transports reject an active TPM policy beforeHTTP. RPM/RPD still apply to all three gateway families. No existing model identity is silently replaced or plugin capability invented. Any adapter whose actual usage exceeds its bound fails future admission for that group rather than manufacturing a refund.

## Acceptance and honest limits

Genuine tests must prove independent clients share RPM/RPD, aliases share only explicit groups, TPM unknown/invalid usage is retained, lower known usage settles once, every retry is charged, another client sees shared429 cooldown, cancellation holds no HTTP concurrency permit, and committed debit survives lost worker/connection and persistent broker restart. Existing P08 concurrency tests are reused, not copied. A real native broker HA failover scenario is separate from simple restart; current-head vendor/Kubernetes and production capacity remain parent-controlled acceptance. No whole-JMS/HA claim precedes executable evidence.

## Review refinements, 11 October 2026

A debit is admitted before the diagnostic DB START. After that START, a second short broker transaction must consume exactly that same still-live receipt once and conservatively move its admission time forward to physical-start admission. This only extends occupancy. A missing, expired, previously started/settled, clock/policy-incompatible or commit-uncertain receipt authorizes zero HTTP; no fresh debit or refund is synthesized. A concurrent cooldown also blocks start. The captured ordinary analysis checkpoint is checked throughout this second transaction, including after confirmed commit. Usage settlement can reduce a token debit only after a confirmed physical start, with complete coherent provider fields and exactly one CAS. HSQL DB START followed by a simulated >minute+2skew worker pause and concurrent consumption are executable regression requirements.

The initial supported production transports remain RPM/RPD-capable and **fail closed for active TPM** until an actual complete-input bound and enforced complete-output cap can be demonstrated. The documented128000 GPT-4o-mini context and16384 output bound, plus `max_completion_tokens`, do not alone prove that a rejected oversized wire input could not incur usage above that reserve. OpenAI's own cookbook qualifies chat-framing counts as estimates. No fixed guessed framing overhead or character-to-token estimate becomes a hard guarantee. A future supported adapter must version the exact model/input contract, validate the whole emitted request (system/catalogue/roles/tools included), emit the real output cap, and append those semantic constraints to frozen recovery fingerprints; TPM-off fingerprints remain byte-identical. The current fixtures prove the durable TPM accounting protocol under an explicit bounded fixture contract, not paid-provider input semantics.

Primary evidence: [GPT-4o-mini model metadata](https://developers.openai.com/api/docs/models/gpt-4o-mini), [Chat Completions create/max_completion_tokens](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [official token-counting cookbook source](https://github.com/openai/openai-cookbook/blob/main/examples/How_to_count_tokens_with_tiktoken.ipynb). OpenAI's Responses input-token counting endpoint counts a different wire protocol; it cannot be silently substituted as an exact preflight proof for the existing Chat Completions transport. No live model call is made during these checks.

Long or overflowing Retry-After durations saturate the durable shared deadline at Long.MAX_VALUE. They must not fail only the initiating caller while permitting independent workers to acquire a fresh debit. Shorter later cooldowns never reset that deadline. The genuine native independent-client regression demonstrates the original fault and the corrected permanent shared hold.

Receipt expiry closes its refund window, not a retained confirmed-start bound observation. The private local durable receipt marks confirmed start only after the actual commit and ordinary checkpoint both succeed. That nonportable proof may stop its exact policy/adapter group after independent pruning; it cannot refund a missing ID and is not recreated from JMS, UUID or archive. Unstarted/commit-unconfirmed receipts have no such usage authority.

Artemis management messageCount sums independently read metrics; it is never ledger authority. Provisioning and every worker validate exclusive durable ANYCAST consumer semantics. After the first state receive, that same exclusive consumer performs a forced-immediate second receive in the same transaction. An actual second state rolls back; the broker end-marker, not a numeric count or cached peek, confirms absence. A dedicated virtual receiver is bounded by the ordinary transaction deadline and checkpoints; cancellation/uncertainty terminates it and closes the transaction before HTTP. Only exceptional consumer close may unblock a stuck receive; normal session operations do not overlap the receiver. Native fault injection must cover actual one/two states under misleading statistics, nonexclusive rejection, in-delivery duplicates, lost end-marker cleanup, parallel admission and HA.
